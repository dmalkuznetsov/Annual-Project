# Применение LLM для извлечения информации из текстов (RAG, LLM-агенты)

## Цель проекта

Разработать сервис на базе open-source LLM, который:

1. отвечает на вопросы пользователя по загруженным документам (RAG);
2. извлекает структурированную информацию из текста: действующих лиц, действия, связи «подлежащее – сказуемое – дополнение»;
3. делает краткое содержание (суммаризацию) документов;
4. работает как веб-приложение на Streamlit.

---

## Этап 0. Постановка задачи и планирование (1 неделя)

Сформулировать, что именно нужно извлекать:

- Действующие лица (сущности) — люди, организации, объекты (NER);
- Действия — глаголы и события;
- Тройки «подлежащее – сказуемое – дополнение» (Subject–Predicate–Object, SPO);
- Суммаризация — краткое содержание текста;
- Ответы на вопросы по документам (QA через RAG).

Определить язык (русский, английский или оба).

Выбрать метрики качества (см. Этап 6).

Настроить репозиторий (GitHub), окружение (Python, venv/poetry), трекер задач.

**Результат:** техническое задание, список задач и метрик.

## Этап 1. Сбор данных (1 месяц)

### Какие данные

| Источник | Что берём | Для какой задачи |
|---|---|---|
| SQuAD / SberQuAD (вопрос-ответ), Gazeta, Hugging Face Datasets | SQuAD / SberQuAD (вопрос-ответ), Gazeta | QA, суммаризация, извлечение сущностей |
| CNN/DailyMail, XSum | CNN/DailyMail, XSum (суммаризация) | QA, суммаризация, извлечение сущностей |
| CoNLL-2003, WikiNEuRal, Collection3 | CoNLL-2003, WikiNEuRal, Collection3 (NER) | QA, суммаризация, извлечение сущностей |
| Kaggle | Новостные корпуса, датасеты отзывов, статьи, тексты книг | Анализ текстов, тестовые документы для RAG |
| MS COCO (Microsoft Research) | Подписи к картинкам (captions, по 5 на изображение) + размеченные объекты (80 категорий) | Извлечение действующих лиц и действий из коротких описаний; разметка объектов служит эталоном для проверки |
| Собственные документы | PDF, DOCX, TXT (регламенты, учебные материалы, статьи) | База знаний для демонстрации сервиса |

### Как использовать COCO

COCO — набор изображений, но к каждому есть текстовые подписи, например:

> «A man is riding a horse on the beach».

LLM извлекает из подписи:

- лицо — `man`;
- действие — `riding`;
- объект — `horse`;
- место — `beach`.

Разметка объектов COCO (`person`, `horse`) служит эталоном (ground truth): можно автоматически посчитать, насколько верно модель нашла действующих лиц.

Получается бесплатная размеченная выборка для оценки качества извлечения сущностей.

**Результат:** папка `data/raw` с исходными данными и описанием источников и лицензий.

## Этап 2. Разведочный анализ данных (EDA) (1 месяц)

### Как анализирую данные

**Статистика по тексту:**

- длина слов (среднее, медиана, распределение);
- длина предложений в словах и символах;
- длина документов (число токенов — важно для контекстного окна LLM);
- размер словаря, самые частые слова (после удаления стоп-слов);
- частотность частей речи (сколько существительных, глаголов).

**Лингвистический анализ:**

- токенизация и лемматизация (spaCy, natasha/pymorphy3 для русского);
- синтаксический разбор — поиск подлежащих и сказуемых через деревья зависимостей (`nsubj → ROOT`);
- частые сущности (NER) и действия (глаголы).

**Визуализация:**

- гистограммы длин;
- облака слов;
- топ-N сущностей и глаголов;
- граф связей «лицо – действие – объект».

**Эмбеддинги для анализа:**

- проекция векторов документов в 2D (UMAP/t-SNE);
- кластеризация (KMeans/HDBSCAN) — какие темы есть в корпусе.

**Инструменты:** pandas, matplotlib/seaborn, spaCy, natasha, nltk, wordcloud, umap-learn.

**Результат:** Jupyter-ноутбук с EDA и выводами (например: «средняя длина предложения 18 слов → чанк в 300–500 токенов вмещает 15–25 предложений»).

## Этап 3. Предобработка и чанкинг (1 месяц)

- Очистка: удаление HTML, лишних пробелов, служебных символов, приведение к единой кодировке.
- Загрузка документов: PDF (pypdf, pymupdf), DOCX (python-docx), TXT.
- Разбиение на фрагменты (чанки):
  - по предложениям или абзацам;
  - фиксированный размер (300–500 токенов) с перекрытием 10–20%;
  - сравнить несколько стратегий и выбрать лучшую по метрикам RAG.
- Сохранение метаданных: источник, страница, номер чанка.

**Результат:** модуль `preprocessing.py`, обработанные данные в `data/processed`.

## Этап 4. Эмбеддинги и векторная база (1 месяц)

### Модели эмбеддингов (Hugging Face, open-source)

- `intfloat/multilingual-e5-base / e5-large`;
- `BAAI/bge-m3` (многоязычная, хорошо работает с русским);
- `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (лёгкая, быстрая).

### Векторное хранилище

FAISS, ChromaDB или Qdrant.

### Поиск

- семантический (по косинусной близости векторов);
- гибридный: семантический + BM25 (по ключевым словам);
- переранжирование (reranker, например `BAAI/bge-reranker-v2-m3`).

Сравнить модели эмбеддингов по метрикам поиска (Recall@k, MRR).

**Результат:** индекс документов и модуль `retriever.py`.

## Этап 5. LLM и извлечение информации (1 месяц)

### 5.1. Выбор open-source LLM

| Модель | Особенности |
|---|---|
| Qwen2.5 (7B / 14B Instruct) | Хорошо понимает русский, умеет выдавать JSON |
| Llama 3.1 8B Instruct | Популярная, много материалов |
| Mistral 7B Instruct | Быстрая, лёгкая |
| Saiga / Vikhr | Дообученные под русский язык |

Запуск локально: Ollama, llama.cpp (квантизация GGUF, 4-bit), vLLM или transformers.

Для экспериментов можно использовать бесплатные GPU Kaggle/Colab.

### 5.2. Задачи

#### 1. RAG (вопрос-ответ по документам)

Вопрос → поиск релевантных чанков → промпт «ответь только по контексту» → ответ со ссылкой на источник.

#### 2. Извлечение действующих лиц и действий

Валидация структуры через pydantic.

#### 3. Подлежащее и сказуемое

Сравнить два подхода:

- классический — синтаксический разбор spaCy/natasha;
- LLM — извлечение через промпт.

Это даёт базовый уровень (baseline) для сравнения.

#### 4. Суммаризация

- короткие тексты — напрямую;
- длинные — подход map-reduce (суммаризация чанков, затем общая выжимка);
- сравнение с классической моделью (например, mT5/rut5 для русского).

### 5.3. LLM-агент

Агент сам решает, какой инструмент вызвать, в зависимости от запроса:

- `search_documents` — поиск по базе знаний;
- `extract_entities` — извлечение лиц, действий, троек;
- `summarize` — суммаризация;
- `statistics` — статистика текста (длины слов и предложений).

**Фреймворки:** LangChain / LangGraph, LlamaIndex или smolagents (Hugging Face).

**Результат:** модули `llm.py`, `extraction.py`, `summarization.py`, `agent.py`.

## Этап 6. Оценка качества (1 месяц)

| Задача | Метрики | Данные |
|---|---|---|
| Поиск (retrieval) | Recall@k, MRR, nDCG | SberQuAD / SQuAD |
| Ответы (QA) | Exact Match, F1, faithfulness (верность контексту) | SberQuAD, RAGAS |
| Извлечение сущностей | Precision, Recall, F1 | COCO (объекты), CoNLL / Collection3 |
| Подлежащее–сказуемое | Доля совпадений со spaCy и ручной разметкой | 100–200 размеченных предложений |
| Суммаризация | ROUGE-1/2/L, BERTScore | Gazeta, CNN/DailyMail |
| Скорость | Время ответа, потребление памяти | — |

Сравнить: разные LLM, разные эмбеддинги, разные размеры чанков, с RAG и без него.

Дополнительно: LLM-as-a-judge (одна модель оценивает ответы другой) и ручная проверка выборки.

**Результат:** таблицы сравнения и графики в ноутбуке, выбор лучшей конфигурации.

## Этап 7. Сервис Streamlit (1 месяц)

- загрузка документов, чат с документом;
- вкладки: «Вопрос-ответ», «Сущности и действия», «Суммаризация», «Аналитика текста»;
- визуализация: графики длин, облако слов, граф связей «лицо – действие – объект».

### Архитектура

```text
Пользователь → Streamlit
                  → Backend (FastAPI)
                  → Агент → [Поиск в векторной БД | Извлечение | Суммаризация | Статистика]
                  → LLM (Ollama / vLLM)
```

**Результат:** работающий прототип, упакованный в Docker (docker-compose: бот + LLM + векторная БД).
